# NoteBridge 0.1.4 本轮修复说明

本版本在 0.1.3 的基础上继续处理专家评估中的恢复能力与日常使用问题。所有设备请先更新到同一版本，等待坚果云同步后再发布、撤回或重新发布。

## 界面

- 侧边栏 NoteBridge 图标打开操作中心，功能分为日常发布、批量与部署，以及可展开的高级操作。
- 文章菜单保留“预览并发布”快捷项，并增加“操作中心”；原有命令和快捷键仍可使用。
- 发布预览显示文章数量、图片数量和快照大小，并提示较大的图片或批次。批量预览有问题时，可选择没有对应问题的文章重新单独预览；同步记录的全局保护仍然生效。

## 恢复和性能

- GitHub 创建候选提交后、更新分支前，本机保存候选 SHA、父提交、涉及文件的预期哈希及前后记录；恢复时只读核对提交是否在分支历史、相关文件是否仍一致，以及本机设置与记录是否匹配。核实后才恢复记录；无法证明时保留日志并停止。候选提交尚未形成前的 Git 对象不会改变分支。
- 同步记录新增校验和，保留前一份有效内容的 `.backup` 文件；检测到损坏时停止。仅当备份与本机当前状态一致时，可通过操作中心恢复，并保留 `.damaged` 原文件。校验和并非防篡改认证，备份也不能保证坚果云多文件同步原子完成。
- 一次插件运行内，同一 Git blob 的分类解析结果可复用；blob 变化后重新读取。
- 设置中的“站点地址”标明为暂未使用；相对 Markdown 链接仍需人工检查。

## 尚未完成和使用边界

- 尚未完成以文章 ID 为中心的完整状态迁移：改名后改回原名和旧路径复用仍可能被保护规则阻止。不要删除或手改同步记录以绕过。
- 不相关历史文件的基线冲突仍可能阻止整个同步；单篇重新预览不能绕过全局身份和记录冲突。
- 事务恢复不能自动判断所有网络或并发状态：候选提交不在已核实分支历史、文件后来变化、设置或本机状态变化、备份与本机不一致时仍需人工处理。
- 图片按快照总大小提示，并未实现强制容量上限、插件侧自动压缩或图片元数据处理；也没有完整 Markdown 语法转换、主题适配、自动队列和限流恢复。
- 自动测试不等于 iPhone、电脑、坚果云和隔离 GitHub 仓库的真实设备、并发及断电验证。生产使用前请备份并验证；旧版本设备不应与新版本同时执行发布或撤回。
