# NoteBridge 0.1.3 修复说明

本次按《NoteBridge 评估与优化建议》优先处理隐私和日常发布恢复问题；评估报告提出的长期架构重构尚未全部实现。

## 已实现

- 统一文章属性和标识解析，正确处理 UTF-8 BOM，避免草稿属性和非公开属性被当作正文上传。
- 默认在上传副本移除正文中的 Obsidian `%%...%%` 和 HTML 注释；代码示例和转义保留，未闭合注释阻止发布。保留 Hexo `<!-- more -->` 摘要标记。预览显示移除类别及数量，最终提交前再次检查隐藏注释和内部字段。
- 撤回时保存可同步的撤回事件：旧设备的历史记录不会恢复已撤回的映射；状态面板显示已撤回，必须明确运行“重新发布已撤回的当前文章”，再单独预览和确认提交。撤回目标在远端再次出现时停止并提示核对。
- 历史合并记录与新本地修改重叠时，冲突命令可以打开可编辑的三方比较；状态面板使用与预览相同的合并计算，避免误报待同步。如果 GitHub 文件也同时变化，仍会保守停止，需要先核对。
- 在本地添加文章标识前保存待登记记录。若写入标识后登记中断，本机下次预览可以恢复登记；对没有该待处理记录的未知标识仍拒绝自动认领。
- 相对 Markdown 文章链接在预览中提示检查网页路径；共享图片在同一批次中只读取一次；长文章在两边相同或一边未变时采用快速合并。
- 保留 0.1.2 的已删除旧关联核对入口和状态刷新优化。

## 更新注意

所有参与发布的设备必须先安装同一个 0.1.3 或兼容的更高版本，并等待坚果云同步笔记、图片和 `NoteBridge同步记录` 后，再使用撤回及重新发布。旧版不理解新的撤回事件。更新插件只替换 `manifest.json`、`main.js` 和 `styles.css`，保留已有设置及同步记录。更新后重新启动 Obsidian 或重新启用插件。

## 尚未完成

- 改名后改回原名、旧路径安全复用，以及以稳定 ID 为中心的完整事件化状态迁移。
- GitHub 提交成功后应用突然退出等情况的完整事务日志、候选提交恢复，以及同步文件校验和备份恢复协议。遇到提交结果不确定或同步记录写入失败时，先检查 GitHub 和两端记录，不要盲目重试。
- 与本次发布无关的历史基线错误仍可能阻塞操作；尚未实现按依赖闭包隔离冲突及手动选择无冲突子集。
- 分类缓存、图片容量预算、逐项上传进度、全面 Markdown 语法支持、主题适配和自动图片压缩等后续建议尚未实现。
- 自动化测试不能替代 iPhone、桌面、坚果云及隔离 GitHub 仓库的真实故障和并发测试；特别是旧版设备重新上线及多设备离线同时操作，仍需谨慎。
